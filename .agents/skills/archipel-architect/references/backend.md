# Backend integration

Use with common Backend, Backend safety and the production-specific test guidance. Read [backend coding standards](../../../../.github/instructions/backend-coding-standards.instructions.md) and [platform source conventions](../../../../.github/instructions/platform-library-source.instructions.md) for affected NestJS/TypeScript code.

- Platform modules and providers live in their owning `libs/platform-*` package. Apps and consuming products compose them; application models and business-domain errors are not framework contracts.
- Controllers map I/O and delegate. Services orchestrate reusable behavior, transactions and queries; they do not construct response DTOs or add `toResponse()` helpers. Use `platform-mapping` profiles and exported typed mapping keys at the transport boundary. Canonical owner: `libs/platform-mapping/src/MappingService.ts`.
- Persistence uses the owning repository's `execute(query)` contract and typed operators; do not bypass it with direct Prisma/delegate calls from services. Read the actual `RepositoryBase`/`Repository2Base` and query family being extended; do not introduce a second repository abstraction or silently migrate between the two.
- `libs/platform-database` owns database services, repository operators, transaction integration and persistence-error translation. Prisma entities/schema generation belongs to the configured generators and consuming schema. Do not add product tables, migrations or a second Prisma client merely to satisfy a framework helper.
- Wrap SDK failures in the owning library's typed platform errors. HTTP-facing errors may extend `ProblemDetailException`; infrastructure errors such as `RepositoryError` remain in their package and are mapped by that package's filter. Do not turn all platform errors into consumer business errors or expose raw provider errors.
- `libs/platform-bootstrap/src/steps/useApi.ts` composes the Problem Details and repository filters plus class-based and Standard Schema validation/serialization. Reuse its public options; preserve filter precedence, HTTP statuses and legacy compatibility when extending it.
- Read [backend contracts](backend-contracts.md) for requests, responses, serialization, OpenAPI and generated clients. Read [platform integration](platform.md) for external I/O, configuration, lifecycle, health and bounded resources.
- Tests must prove the contract at its owner and the distinct consumer seam affected by the change: query execution/error classification, DTO mapping, registration/injection, request validation, response serialization or provider behavior. A mocked downstream projection does not prove the upstream contract.
