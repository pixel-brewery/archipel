# Tooling, generators and documentation

Use for package documentation, Prisma generation, the documentation MCP server, repository executors and changes to developer guidance. Read the relevant documentation/tooling sections of [Archipel conventions](../../../../.github/instructions/archipel-project.instructions.md).

- Source owners: `tools/mcp` provides documentation discovery/guides/pattern generators; `tools/prisma-generator-entities` and `tools/prisma-generator-json-schema` own Prisma generator output; `infra/nx-plugins` owns the package-documentation executor. Discover each resolved Nx project and target before execution; the documentation MCP project's name is `mcp-server`.
- Library package READMEs ship with the package. Locate actual authored package pages, `.docs/guides/`, `.docs/patterns/` and architecture pages for the public contract, configuration, provider choices and consumer setup; not every generated package API directory has an authored `index.md`. Keep all affected authored surfaces aligned with verified source, without copying product-specific handbooks into Archipel.
- `.docs/packages/<package>/api/` is generated from TypeScript/TSDoc by `nx-plugins:generate-package-docs` in `infra/nx-plugins/src/executors/generate-package-docs`. Run the owning `yarn nx run <project>:docs` target rather than editing generated pages. Respect shared-output ordering when several subagents touch source or generation.
- The MCP server consumes and packages documentation from `.docs/packages`, `.docs/guides` and `.docs/patterns`; its build depends on upstream docs. A documentation change can affect MCP-delivered content even when no MCP TypeScript changed. Verify the affected packaging/discovery path when that consumer contract changes.
- Generated Prisma entities/schema files are outputs, not the editing source. Trace the actual generator implementation, schema/options and consuming import contract before changing a type mapping; regenerate representative output and verify its semantic contract. Do not substitute a handwritten generated file or consumer-specific model inside the framework.
- Use the existing public docs and generator patterns; do not create a second docs source, copied generator, local backlog or alternate agent instruction tree. New architectural guidance belongs in this native skill's shared or project-specific owner, as appropriate.
- Check local Markdown links, task-scoped whitespace and affected generated/source consistency. Run the relevant docs-site build or tool tests when rendering, generation or packaged content is affected; instruction-only edits need focused skill/link/synchronization validation rather than an invented full product gate.

## Architecture dependency

`archipel-architect` derives from `.agents/skills/architecture/SKILL.md`, installed from `pixel-brewery/skills` through the Skills CLI. Root `skills-lock.json` records the reviewed full commit and content hash. Run `yarn agents:check` to validate the dependency and explicit inheritance after updates. Keep project-specific rules in `archipel-architect`; common rule changes belong upstream and arrive through an intentional versioned update. The helper named `sync_architect_core.py` is now read-only validation; it never copies private skill content to another checkout.
