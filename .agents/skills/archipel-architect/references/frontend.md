# Frontend and documentation website integration

Use with common Frontend, Frontend patterns and the relevant testing guidance only when an actual frontend owner is involved. Read the applicable sections of [frontend standards](../../../../.github/instructions/frontend-coding-standards.instructions.md).

- The current frontend owner is the VitePress documentation website under `apps/frontend/docs`, with authored documentation under `.docs/`. Read its actual VitePress/Vue configuration and existing theme/components before extending navigation, rendering or examples.
- Angular/Lit guidance applies to real Angular/Lit source when present; it does not require migrating the documentation website or creating an Angular product shell. Do not import FLAMOX365 presenters, feature providers, tenant state, locale catalogs or Mosaik-specific theme/catalog infrastructure into this framework repository.
- Preserve existing documentation navigation, authored versus generated content boundaries, code examples and package links. API Markdown under `.docs/packages/*/api/` is generated by the package-doc executor; change its source/generator instead of patching output.
- For a visible website change, inspect the existing equivalent view and verify the affected rendered route. Use the configured docs project targets; do not claim a Playwright journey or browser result from a static document check.
- Shared behavior and meaningful test rules govern legacy frontend examples: do not create tests that pin styles, icons or generic control copy. If browser automation is requested and configured, use the shared explicit `test-id` contract rather than copying older role/text selector examples.
- Read [tooling and documentation](tooling.md) for docs generation and the MCP consumer of documentation, and [testing](testing.md) for actual runner/browser availability.
