# Transport projection and generation

Use with common Backend contracts and API URL guidance. Read [backend coding standards](../../../../.github/instructions/backend-coding-standards.instructions.md) and [API guidelines](../../../../.github/instructions/api-guidelines.instructions.md) for the affected transport.

- Archipel supplies the framework contract in `libs/platform-core`, bootstrap integration in `libs/platform-bootstrap`, and feature/OpenAPI discovery in `libs/platform-openapi`. A consuming application owns its controllers and generated clients; consumer-specific client projections and Mosaik's frontend transport are separate integrations whose availability must be verified.
- New supported request/response contracts use named Standard Schema models and inferred types. Preserve decorated legacy request/response classes where their integration has not been migrated. Bootstrap enables both schema-native processing and the legacy `ValidationPipe`; inspect the selected options and actual consumer.
- Canonical envelope owner: `libs/platform-core/src/models/ResponseReturn2.ts`. Build one stable `ResponseReturn2.schema(DataSchema, optionalEnvelopeId)` and use that full wire schema for `@SerializeOptions` and OpenAPI. Pass the exact `DataSchema` instance to `ok`, `created` or `accepted` so transforms run once. Align controller HTTP status and envelope status; a 204 has no body or serializer schema.
- Archipel's schema includes the `x-archipel-envelope` metadata describing version and payload property. The metadata is a capability for compatible generators, not evidence that every consumer unwraps envelopes. Verify each generator/transport integration before migrating an existing client projection.
- Preserve schema identity, request/input versus response/output conversion, component references, additional-property behavior and transformed values. Keep class fallback separate from a schema-native path rather than validating one contract while documenting another.
- `useApi` owns default Standard Schema validation/serialization and library error filters; `platform-openapi` owns Swagger feature discovery and generated documents. Extend these existing public integration paths instead of adding a second serializer or discovery registry.
- Verify real request rejection, response transformation, wire body, HTTP status, OpenAPI schema and any changed consumer projection. Use the existing `ResponseReturn2.spec.ts` and `useApi.spec.ts` as contract references; do not claim generated-client compatibility from package metadata alone.
