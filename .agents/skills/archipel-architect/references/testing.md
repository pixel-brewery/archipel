# Test integration

Use with the common Testing or Browser E2E module and every affected production domain. Read the relevant [testing standards](../../../../.github/instructions/testing-standards.instructions.md); treat [older Playwright examples](../../../../.github/instructions/testing-e2e-writing-guidelines.instructions.md) as examples subordinate to the shared selector/ownership rules and executable configuration.

All execution and fixtures follow [Environment](environment.md), including one globally coordinated heavy task and one test worker. Existing root-script parallelism does not grant parallel execution on the shared machine.

- Vitest owns unit and integration tests. Inspect root and project `vitest.config.*`, Nx plugin configuration and `yarn nx show project <name> --json`; do not assume all projects have the same inferred targets. Use configured runners and package versions, never a Jest replacement or an incidental “latest stable” upgrade.
- Add tests for observable behavior, decisions, validation, state, lifecycle, failure handling and public contracts. New public service behavior needs successful and failing cases; do not multiply equivalent assertions across layers or add tests for copy, stylesheet output or trivial delegation.
- Follow AAA with one material Act, deterministic mocks and timers, `vi.restoreAllMocks()` and cleanup.
- Before creating, renaming or extending a spec, read the real production owner and its existing spec. Source specs live beside that owner and use its exact basename and casing with only `.spec` inserted: `Class.ts` → `Class.spec.ts`. Removing `.spec` must name the existing production file. Unit, integration, PostgreSQL, contract, API and regression tests all follow this rule; runner configuration selects execution, never extra scenario or technology suffixes such as `.postgres.spec.ts`.
- Add scenarios to the owner's suite; use the real coordinating owner or distribute assertions across actual owners for behavior spanning files. Keep helpers and fixtures as ordinary adjacent modules. Existing orphan scenario specs and separate test directories are cleanup work, never precedent: consolidate affected cases into the real owners' specs and remove the orphan. Never add an empty production file, barrel or harness class to manufacture ownership. Verify imports, runner discovery and build exclusions after moves; browser exceptions follow the explicit local browser contract.
- Use Nest's testing module and provider overrides for DI behavior. Integration tests use actual selected modules and persistence/transport boundaries where those are the subject; mocks prove only the mocked layer. Provider contracts need relevant successful responses, rejected/invalid payloads, timeouts and supported retry/error behavior.
- Real PostgreSQL integration uses only the existing configured main database/schema owned by the consuming project. Archipel's type-generation stub and dummy connection strings in mocked unit tests do not identify such a runtime. Never create/drop/clone a database or test schema, start Testcontainers, run `db push`, replay migrations, reset shared tables or disable triggers for a test. Rewrite incompatible fixtures when asked to run all tests; skipped database cases are not a complete pass.
- Verify the configured and actual database, address, port and schema before writes. Use uniquely marked fixtures with explicit scoped cleanup, or a complete real outer rollback for global cleanup queries. Keep every operation inside its chosen transaction and preserve actual independent transactions for concurrency evidence. Do not replace the disputed persistence boundary with a mock to protect shared data.
- Test installed schema/defaults and current persisted behavior through actual owners instead of dismantling the main schema for historical migration replays; describe that evidence accurately. Immutable successful writes remain inside rollback, with any real inter-transaction lock proof kept distinct.
- Bootstrapped HTTP tests use Supertest where installed/configured and share the single coordinated application runtime. Reuse it or deliberately replace its owner on the configured port; never start an extra API on an ephemeral/alternate port because another instance is busy. In-process module tests without a server listener remain ordinary unit/DI tests.
- Mirror the real `useApi` bootstrap: Standard Schema validation and response serialization coexist with legacy class validation, and package errors map through their actual filters. Prove wire statuses, error shape and transformation with meaningful contract tests rather than constructor/metadata-only assertions.
- Coverage thresholds come from the effective Vitest configuration: root currently configures 80 for statements, branches, functions and lines; the historical 85/90 prose is not an executable gate. An individual project's overrides may differ. Coverage does not replace behavioral evidence.
- Resolve focused lint/test/build/typecheck targets through Nx. Root `typecheck` currently runs backend builds; do not label it an independently configured typecheck suite. Packaging changes also require build and relevant public ESM entry-point verification. `tools/mcp` has build/documentation prerequisites that a library unit suite does not prove.
- No checked-in Playwright configuration or browser suite is currently established by the package manifests. A generic Playwright instruction file does not create a runnable E2E gate. For a browser task, combine common Browser E2E with [browser integration](e2e.md); report a missing prerequisite instead of inventing a suite or claiming completion.
